# Model Card — прогноз явки волонтёра (erik)

Короткий паспорт модели для защиты и код-ревью. Все числа получены на отложенном
тесте со сплитом **по волонтёрам** (история одного человека не попадает разом в train
и test) и воспроизводятся: `python train.py && python evaluate.py && python baseline.py`.

## Задача

Бинарная классификация: **придёт ли конкретный волонтёр на конкретный сбор** —
`P(came = 1 | история волонтёра, тема сбора, ответ)`. Сумма вероятностей по участникам
= ожидаемая явка сбора.

## Данные

- Источник: синтетический причинный журнал (`data_gen.py`) — реальной истории сборов
  пока нет. Генеративная «правда» задаёт латентную надёжность, симпатию к темам,
  усталость и шум; **модель этих скрытых параметров не видит** — только наблюдаемую
  историю.
- Объём: **26 553** записи RSVP от **1 200** волонтёров. Баланс классов: **0.638** «придут».
- Сплит: `GroupShuffleSplit` по `volunteer_id`, test = **5 030** строк.

## Признаки (14, считаются причинно — только по истории ДО сбора)

История явки (`events_total/came/missed`, `attendance_rate` со сглаживанием Лапласа,
`reliability`), свежесть (`recent_came_rate`, `days_since_last`), история по теме
(`theme_total/came`, `theme_attendance_rate`), совпадение темы с интересами
(`interest_match`, `num_interests`), ответ (`answer`), тип сбора (`event_type`).

Единая `features.compute_feature_row()` для train и inference → нет train/serve skew.

## Модель

- **HistGradientBoostingClassifier** (one-hot для категорий) +
- **изотоническая калибровка** (`CalibratedClassifierCV`, cv=3) — обучаемое монотонное
  преобразование скоров в честные вероятности. Именно она делает `Σ p_i` осмысленной
  ожидаемой явкой (заменила прежнюю ручную степень `p**γ` в мосте бэкенда).

## Качество (отложенный тест, n = 5 030)

| метрика | значение |
|---|---|
| ROC-AUC | **0.793** |
| PR-AUC | 0.841 |
| F1 (класс «придёт») | 0.806 |
| Accuracy | 0.731–0.738 |
| Brier score | **0.175** |
| Log-loss | 0.525 |

## Почему это модель, а не формула (сравнение на том же тесте)

| предсказатель | ROC-AUC | Brier | ожидаемая явка Σp (факт = 3116) |
|---|---|---|---|
| «по ответу» (повторяет число подтвердивших) | 0.698 | 0.199 | 3226 |
| матформула `base·trust·ctx` | 0.753 | 0.322 | 1334 (−57%) |
| **эта модель (калибр.)** | **0.793** | **0.175** | **3188 (−2.3%)** |

- Модель обыгрывает эвристику «по ответу» на **+0.095 ROC-AUC**: наивная ставка «по
  ответу» может угадать *сумму* (арифметика), но не ранжирует, **кто именно** придёт.
- Модель обыгрывает аналитическую формулу на **+0.040 ROC-AUC** и в разы точнее по
  калибровке (Σp попадает в фактическую явку с ошибкой ~2% против −57% у формулы).

Что это значит на людях (демо-инференс):

| волонтёр | ответ | P(придёт) |
|---|---|---|
| надёжный, тема из интересов | да | **0.95** |
| новичок без истории, тема из интересов | да | **0.84** |
| флаки, чужая тема | может быть | **0.16** |
| средний | нет | 0.16 |

Новичок-«да» (0.84) осознанно ниже проверенно-надёжного «да» (0.95) — формула по ответу
дала бы им одинаковую вероятность.

## Важность признаков (permutation, падение ROC-AUC)

`answer` (0.134) → `interest_match` (0.052) → `attendance_rate` (0.015) →
`reliability` (0.010) → `days_since_last` (0.004) → …

Ответ — сильнейший сигнал (и должен им быть), но вклад несут и совпадение по интересам,
и накопленная надёжность, и свежесть активности. Это то, чего формула по ответу лишена.

## Ограничения и развитие

- **Данные синтетические.** На проде модель переобучается на журнале `AttendanceRecord`
  (неизменяемый источник истины) — код обучения не меняется, меняется только источник.
- `answer` доминирует — на реальных данных ожидаем рост вклада истории/темы.
- Модель — компаньон аналитической формулы (`services/forecast.py`): формула быстрая и
  всегда доступна (фолбэк), модель — точнее, когда обучена. Мост
  `backend/services/attendance_ml.py` мягко деградирует, если артефакта нет.
