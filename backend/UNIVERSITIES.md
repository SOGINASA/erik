# Университетские сообщества

Раздел `/universities` показывает каталог вузов и их мероприятия. Заявка на вступление
содержит ФИО, телефон и фото студбилета (PNG/JPEG/WebP до 5 МБ). Назначенный координатор
или администратор одобряет заявку либо отклоняет с причиной; студент получает
уведомление и может исправить заявку. Студбилет хранится в БД и выдаётся только
заявителю, назначенному координатору и администратору с авторизацией и `no-store`.

Одобренные участники записываются через существующий цикл мероприятий, включая роли,
подтверждение участия, QR-явку и учёт часов. Проверка членства действует на обычную
запись, RSVP по коду и заявку организатору. Общая лента показывает общие мероприятия;
мероприятия вузов находятся на страницах университетов и в списке собственных участий.
Просматривать описание мероприятия можно до вступления.

## Обновление существующей установки

Из каталога `backend`, в окружении приложения:

```sh
pip install -r requirements.txt
flask db-sync
flask seed-catalogs
```

`db-sync` поддерживает существующие БД, созданные как миграциями, так и `create_all`.
В production стандартный entrypoint также выполняет синхронизацию и загрузку каталогов.
Сборка фронтенда: `cd front && npm ci && npm run build` из корня репозитория.

Каталог `university_catalog.json` содержит 108 записей из
[справочника Национального центра развития высшего образования](https://enic-kazakhstan.edu.kz/page/Organizations_of_higher_and_(or)_postgraduate_education),
загруженного 5 ноября 2026 года. Это снимок справочника, а не обещание актуальности
всех названий, сайтов или полноты действующих вузов. Начальные записи не означают,
что университет уже сотрудничает с платформой. `seed-catalogs` добавляет отсутствующие
записи, сохраняя изменения администратора в существующих карточках.

В админке `/admin/universities` можно добавлять вузы. Откройте карточку →
«Настройки университета» → укажите ID активного координатора (роль `coord` или `org`).
Координатор видит раздел заявок и кнопку создания мероприятия на странице своего вуза.
Мероприятия проходят обычную модерацию перед публикацией.

## Подключение Microsoft Entra

Без приложения Microsoft раздел работает через студбилеты; кнопка Microsoft скрыта.
Интеграция подтверждает принадлежность существующего профиля erik к вузу. Для первого
визита студент сначала создаёт профиль erik, затем выбирает Microsoft на странице вуза.

1. В Microsoft Entra admin center откройте **App registrations → New registration**.
   Для подключения нескольких независимых вузов выберите **Accounts in any
   organizational directory**. Личные Microsoft-аккаунты не используются.
2. Добавьте платформу **Web** с redirect URI публичного backend:
   `https://<api-домен>/api/universities/microsoft/callback`.
   Для локальной разработки допустим `http://localhost:5000/api/universities/microsoft/callback`.
   URI должен совпадать с `MICROSOFT_REDIRECT_URI` дословно. Implicit flow не требуется.
3. Сохраните Application (client) ID. Создайте client secret и сохраните его **Value**
   в окружении сервера. Секрет не должен попадать во фронтенд, Git или переписку.
4. В **API permissions** используйте делегированное разрешение Microsoft Graph
   **User.Read**. Согласуйте разрешение приложения с IT-службой каждого вуза:
   политика его каталога может требовать административного согласия.
5. Настройте сервер и перезапустите backend:

   ```dotenv
   MICROSOFT_CLIENT_ID=<application-client-id>
   MICROSOFT_CLIENT_SECRET=<secret-value>
   MICROSOFT_REDIRECT_URI=https://<api-домен>/api/universities/microsoft/callback
   FRONTEND_URL=https://<домен-фронтенда>
   ```

6. В настройках карточки вуза укажите **Directory (tenant) ID именно этого вуза**
   и разрешённые домены, например `students.example.edu.kz`. Эти значения должна
   подтвердить IT-служба университета. Домены не определяются автоматически из сайта.

Вход использует Authorization Code Flow с PKCE, одноразовым `state` (10 минут), `nonce`,
проверкой подписи ID token, issuer, audience и точного tenant ID. Затем Graph `/me`
подтверждает тот же `oid`, тип пользователя `Member` и точный домен
`userPrincipalName`. Личные аккаунты, гости каталога и другие домены не получают доступ.
Один Microsoft-аккаунт может быть связан только с одним профилем erik в данном вузе.
Токены Microsoft не сохраняются и не передаются фронтенду.

Успешная проверка автоматически одобряет членство. **Корпоративный аккаунт подтверждает
принадлежность к каталогу, а не статус студента**: если домен общий для студентов и
сотрудников, сотрудники тоже смогут вступить. Для ограничения студентами настройте
отдельный студенческий домен; если его нет, используйте ручную проверку студбилетов.

Проверка без реального Entra-приложения покрыта тестами с подписанными тестовыми
токенами и заглушками Microsoft. Перед включением для пользователей проверьте полный
вход с тестовой корпоративной учётной записью в каждом подключаемом вузе.

Документация Microsoft:
[Authorization Code Flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow),
[Microsoft Graph: Get user](https://learn.microsoft.com/en-us/graph/api/user-get?view=graph-rest-1.0).
